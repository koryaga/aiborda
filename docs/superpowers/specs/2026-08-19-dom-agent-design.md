# DOM-агент: спецификация

Дата: 2026-08-19. Заменяет `PLAN.md`; расхождения разрешаются в пользу этого
документа.

Веб-приложение, в котором LLM живёт внутри страницы. Пользователь правит DOM
руками — в полях ввода и через Chrome DevTools — и нажимает «отправить».
Модель получает диф правок, отвечает JavaScript-кодом, код исполняется и
меняет тот же DOM. Образ одновременно интерфейс, состояние и память агента.

Инварианты:

1. Код модели всемогущ внутри образа и бессилен снаружи.
2. Состояние страницы не попадает в контекст извне. От пользователя приходит
   только диф; состояние модель читает сама, когда сочтёт нужным.

Единственная санкционированная уступка инварианту 2 — карта образа после
сброса истории (§3). Карта не содержит ни одного символа пользовательских
данных: только структуру и длины.

---

## 0. Проверенное на стенде

Спайк на `sandbox="allow-scripts"` + `srcdoc`, поднятый на `127.0.0.1`.
Результаты — основание для §1, §6 и §12, а не предположения.

| Проверка | Результат |
|---|---|
| `new Function('return (async()=>{…})()')` | работает |
| `localStorage` | `SecurityError` |
| `document.cookie` | `SecurityError` |
| `parent.document` | `SecurityError` |
| `fetch('https://example.com')` | `TypeError` |
| `fetch('/index.html')` (свой же сервер) | `TypeError` — opaque origin, CORS |
| `parent.postMessage` из образа | **проходит** |
| `event.origin` в оболочке | всегда `"null"` |
| `event.source === frame.contentWindow` | различает корректно |
| `MutationObserver`: `oldValue`, `removedNodes`, `addedNodes` | все работают |
| `.value` живого поля виден наблюдателю | **нет** |
| синтетическое событие | `isTrusted === false` |
| мутации кода модели → диф | **пустой** (атрибуция работает) |

Не проверено автоматизацией и требует ручного подтверждения: доставка
синтетического ввода в sandbox-фрейм инструментом не проходит, поэтому
живой набор человека и правки через DevTools проверяются руками на стенде.

Два вывода, не отражённых в исходном плане:

- `event.origin` бесполезен как проверка: у любого sandbox-фрейма он `null`.
  Единственная валидная сверка — `event.source` плюс совпадение `id` с
  ожидающим запросом.
- `getAttribute()` в момент доставки записи наблюдателя возвращает **текущее**
  значение, а не значение на момент мутации. Две правки одного атрибута дают
  две записи, первая из которых уже содержит конечное «новое». Наивный проход
  по записям даёт лишние и неверные строки дифа — требуется коалесцирование
  (§6).

## 1. Топология

| Контекст | Что это | Полномочия |
|---|---|---|
| Сайдкар | Node-процесс | ФС, сеть, ключи, конфиг pi, история контекста |
| Оболочка | страница в браузере | кнопки «отправить», «пауза», «сброс»; индикатор |
| Образ | `<iframe sandbox="allow-scripts">` | только свой DOM |

Образ имеет opaque origin: нет `localStorage`, нет `document.cookie`, нет
доступа к `parent`, любой `fetch` умирает на CORS — включая запрос к тому же
серверу, который отдал оболочку. Навигация запрещена.

Кнопки находятся в оболочке, вне iframe: код модели не должен мочь их убрать
или нажать.

Человек — второй всемогущий житель образа: через DevTools он правит DOM и
может исполнять код в контексте фрейма. Это осознанная часть дизайна, а не
дыра: инвариант 1 ограничивает модель, а не автора.

### Seed образа (`web/seed.html`)

```html
<textarea id="q" rows="3"></textarea>
<ul id="items"></ul>
<div id="out"></div>
<div id="notes" hidden></div>
```

Модель вправе менять что угодно, включая seed.

### Вне объёма v1

Поля промпта и чата нет. Approval-гейта нет. Доступа модели к ФС и сети нет.
`contenteditable` по умолчанию не включается. Бандлера и React нет: один HTML
и ES-модули.

## 2. Цикл хода

1. Человек правит образ: набирает в полях либо редактирует DOM в DevTools
2. Наблюдатель мутаций и слушатели полей копят правки (§6)
3. Человек жмёт «отправить»
4. Оболочка запрашивает у образа диф
5. Сайдкар собирает контекст, зовёт модель, стримит ответ
6. Код применяется в образе, накопленные записи очищаются
7. Оболочка запрашивает снапшот и держит его как последний известный (§6)

Один ход за раз. Правки во время хода копятся и уезжают следующим ходом.
Повторное «отправить» ставит в очередь ровно один отложенный ход.

«Пауза» прерывает текущий ход и блокирует отправку.

## 3. Сборка контекста

История хранится в сайдкаре, per-session. Снапшота в контексте нет никогда.

```
system:     контракт (§7), статичный, включая описание окружения
user:       диф правок человека
assistant:  <код>
user:       результат: <возвращённое значение>     ← если код что-то вернул
assistant:  <код>
user:       диф правок человека
```

Правила:

- снапшот образа в запрос к провайдеру не кладётся ни при каких условиях
- снапшот не кладётся в системный промпт
- отправленные сообщения не редактируются и не удаляются по одному
- `system` не меняется между ходами
- если код вернул значение — оно уходит следующим сообщением `результат: …`;
  если вернул `undefined` — сообщение не добавляется

Префикс не переписывается, KV-кэш переиспользуется: префилл платится только
за новый диф.

### Сброс истории

`history = []`. Без суммаризации.

Триггеры:

- оценка контекста превысила 60% от `contextWindow` модели; если поле
  отсутствует — 24k токенов по оценке 4 символа на токен
- два хода подряд завершились ошибкой исполнения
- кнопка «сброс → история» в оболочке

После сброса модель не знает состояния страницы. Чтобы она не тратила
следующий ход на чтение, сайдкар один раз добавляет карту образа отдельным
сообщением, **перед** дифом:

```
user: результат: [история сброшена] <карта>
user: <диф>
```

Это единственный случай, когда `результат:` приходит без предшествующего
сообщения `assistant`. Формат переиспользуется намеренно: для модели это тот
же канал чтения состояния, что и возврат значения из её собственного кода.

### Карта образа

Запрашивается у образа сообщением `{type:'map', id}`. Содержит структуру и
размеры, но не содержимое:

```
body
  #q        textarea   value:14
  #items    ul         children:3
    li      text:12
    li      text:9
    li      text:0
  #out      div        children:0  text:31
  #notes    div[hidden] children:2
```

Правила карты:

- ни одного символа пользовательского текста — только длины
- значения атрибутов не выводятся, выводятся только имена флаговых атрибутов
  (`hidden`, `disabled`, `checked`)
- потолок 120 строк или 2000 символов; лишнее сворачивается в
  `… ещё N узлов`
- карта строится только при сбросе; в обычном ходе не запрашивается

## 4. Конфигурация моделей из pi

Читаем `~/.pi/agent/models.json`.

**Решение по проверке `pi-ai` (шаг 0 исходного плана, закрыт):** `@earendil-works/pi-ai@0.84.2` экспортирует
`createModels()`, `createProvider()`, готовые реализации `openai-completions`
и `anthropic-messages`, retry, event-stream и abort. Собственный
`server/providers.js` **не пишется**. Но чтение файлов с диска живёт в
`dist/cli.js` пакета, а наружу торчат только `InMemoryModelsStore` и
`InMemoryCredentialStore` — поэтому маленький собственный загрузчик файла
остаётся.

Требования к загрузчику:

- путь по умолчанию `~/.pi/agent/models.json`; переопределяется
  `PI_MODELS_PATH` и флагом `--pi-config`
- **разворачивать `$VAR`** в значениях: в реальном конфиге встречается
  `"apiKey": "$DEEPSEEK_API_KEY"`
- **провайдер без массива `models`** — легальный случай (в реальном конфиге
  это `ollama`). Список моделей берётся живым discovery у провайдера;
  `modelOverrides` накладываются поверх. Наивный загрузчик даст по такому
  провайдеру пустой список — это ошибка, а не поведение.
- `api`: поддержать `openai-completions` и `anthropic-messages`; прочие
  распознать, пометить unsupported, не падать
- у модели обязателен только `id`; `contextWindow`, `cost`, `input`
  опциональны
- `compat` пробрасывается в pi-ai как есть (`supportsDeveloperRole`,
  `maxTokensField`, `thinkingFormat`, `requiresThinkingAsText`)
- ключ: `apiKey` из models.json, иначе `~/.pi/agent/auth.json`, иначе
  окружение
- **секреты не логируются и не отдаются в браузер из обоих файлов.**
  `auth.json` имеет права 0600, но `models.json` — 0644 и может содержать
  ключ открытым текстом (в реальном конфиге такой есть у провайдера
  `openmodel`). Фильтр по `auth.json` недостаточен.
- конфиг отсутствует или битый → пустой список моделей и текст ошибки
  «не найден ~/.pi/agent/models.json — создайте его или укажите --pi-config»
- перечитывать по SIGHUP и `POST /api/reload`

Браузеру уходит только `{provider, id, contextWindow}`.

## 5. Сайдкар: HTTP API

```
GET  /api/models          -> { models: [{provider, id, contextWindow}], error? }
POST /api/reload          -> перечитать конфиг
GET  /api/session         -> { tokens: int, limit: int }
POST /api/session/reset   -> сбросить историю
POST /api/commit          -> поток хода
POST /api/abort           -> прервать текущий ход
```

`POST /api/commit`:

```json
{
  "model": { "provider": "ollama", "id": "gemma4:12b-mlx-64k" },
  "diff": "#q  \"\" -> \"посчитай маржу\"\n#out  @class: \"v1\" -> \"v2\"",
  "result": "3"
}
```

Снапшот в теле запроса отсутствует.

Отдельного метода для результата исполнения нет. `result` — значение,
вернувшееся из кода на **предыдущем** ходу; сайдкар кладёт его в историю перед
дифом. Так порядок сообщений получается ровно такой, как требует §3, и без
лишнего запроса.

Поток — `text/event-stream`, но **`EventSource` не применим**: он умеет только
GET, а диф в query-строку не помещается. Оболочка читает `ReadableStream`
ответа `fetch` и разбирает кадры сама. События: `delta`, `done` (итоговый
код), `error`.

Сайдкар слушает `127.0.0.1`. Оболочка отдаётся тем же процессом.

## 6. Протокол оболочка ↔ образ

`postMessage`.

Оболочка → образ: `{type:'exec', id, code}`, `{type:'diff', id}`,
`{type:'snap', id}`, `{type:'map', id}`, `{type:'reset'}`

Образ → оболочка: `{type:'ready'}`, `{type:'result', id, ok, value?, error?}`,
`{type:'diff', id, text}`, `{type:'snap', id, html}`, `{type:'map', id, text}`

### Доверие к сообщениям

Код модели может вызвать `parent.postMessage` — проверено, проходит. Значит
образ способен прислать незапрошенный `diff` и подсунуть в контекст
произвольный текст под видом правки человека. Оболочка обязана:

- сверять `event.source === frame.contentWindow`
- сверять `id` со списком ожидающих запросов; незапрошенное сообщение
  отбрасывать
- **не** использовать `event.origin` как проверку: у sandbox он всегда `null`

Инвариант 1 при этом держится: кнопки оболочки коду модели недоступны.

### Захват правок человека

Правки через DevTools не порождают ни `input`, ни `change`, ни `click`.
Механизм на `isTrusted` их не видит. Основа — `MutationObserver`; события
нужны только там, где наблюдатель слеп.

```js
new MutationObserver(rs => {
  for (const r of rs) recs.push({ r, byModel: execDepth > 0 });
}).observe(document.documentElement, {
  subtree: true, childList: true, attributes: true, characterData: true,
  attributeOldValue: true, characterDataOldValue: true,
});
```

Живой набор в поле меняет свойство `.value`, а не атрибут, и наблюдателю
**не виден**. Для полей — отдельные слушатели, запоминающие исходное
значение при первом касании:

```js
for (const t of ['input', 'change'])
  document.addEventListener(t, e => {
    if (!e.isTrusted) return;
    if (!fields.has(e.target)) fields.set(e.target, e.target.defaultValue ?? '');
  }, true);
```

Атрибуты `data-was` и `data-edited` из прошлой редакции **не используются**:
наблюдатель отдаёт старые значения сам, и DOM модели не засоряется.

### Атрибуция: модель или человек

Код модели исполняется только внутри `exec`, и образ знает границы этого
окна:

```js
execDepth++;
… исполнение, отправка result …
setTimeout(() => execDepth--, 250);   // грейс для асинхронных хвостов
```

Мутация с `byModel === true` в диф не попадает. Проверено на стенде: код
модели изменил `#out`, диф пустой.

### Сборка дифа

Коалесцирование обязательно — см. §0.

- **атрибуты**: ключ `(узел, имя атрибута)`; «старое» берётся из самой ранней
  записи. «Новое» — из живого DOM, **но если по тому же ключу есть более
  поздняя запись модели, то из её `oldValue`**: иначе человек правит узел,
  следом его правит код модели, и модель получает собственное значение как
  чужую правку. Это запускает самокоррекцию по кругу — худший из отказов
  здесь. Если старое и новое совпали, строка не выводится.
- **текст**: ключ — узел; правило то же. Ключ именно узел, а не путь: у
  одного родителя бывает два текстовых потомка, по пути они схлопнутся.
- **удаления**: узлы из `removedNodes`, не вернувшиеся в документ; узел
  сериализуется по живой ссылке на отсоединённый узел
- **добавления**: узлы из `addedNodes`, присутствующие в документе на момент
  сборки, по одной строке на узел с последним известным родителем
- **пробельные текстовые узлы не выводятся**: ни добавление, ни удаление, ни
  правка, у которой и старое, и новое состоят из пробелов. Это форматирование
  разметки, а не намерение человека. На реальных дифах такие строки составляли
  22%, и `добавлен в html > body:nth-child(2): "\n\n"` приходило в каждом
  первом ходе сессии. Правка `"\n "` → `"привет"` пробельной не считается и
  выводится
- **поля**: сравнение текущего **состояния** с запомненным исходным.
  Состояние — не всегда `.value`: у флажка и радиокнопки это `.checked`,
  у `<select multiple>` — список выбранных. Элемент без состояния строки не
  даёт, иначе `contenteditable` порождает `"" -> undefined`.

Исходное состояние поля запоминается при `focusin` и после сборки дифа
**пересевается, а не стирается**: фокус из поля не уходил, второго `focusin`
не будет, и на следующем ходу «было» соврёт — а при возврате к исходному
значению правка потеряется совсем.

Путь узла: ближайший предок с `id`, дальше цепочка `tag:nth-child(n)`.
Синтетических идентификаторов в DOM не вносится. Путь, построенный от `id`,
проверяется обратным `querySelector`: `id` бывает неуникальным или
синтаксически негодным после копипаста в DevTools, и тогда модель
отредактирует не тот узел. Отсоединённый узел помечается в строке явно —
его путь адресует другой живой элемент.

Формат:

```
#q                        "" -> "посчитай маржу по регионам"
#out                      @class: "v1" -> "v2"
#items > li:nth-child(1)  текст: "первый" -> "первый пункт"
удалён из #items:         <li id="row-2">второй</li>
добавлен в #items:        <li id="row-3">третий</li>
```

Диф **полный, без потолка**: содержимое добавленных поддеревьев уходит
целиком. Принятое следствие: правка большого блока через Edit as HTML
способна занять существенную долю окна и тригернуть сброс сразу за собой.
Цена — один лишний ход, потери нити нет, потому что после сброса приходит
карта (§3).

HTML в строках удаления и добавления идёт с схлопнутыми переносами строк:
все прочие строки экранированы через `JSON.stringify` и однострочны, а сырой
`outerHTML` форматированного элемента разворачивается в несколько строк и
ломает контракт «строка дифа = одна правка».

После сборки буферы записей очищаются, состояния полей пересеваются.

### Сериализация снапшота

`innerHTML` не содержит `input.value`, `checked`, `selected` и содержимое
`textarea`. Синхронизация делается **на клоне**, а не на живом DOM: живой DOM
является памятью агента, и мутировать его ради сериализации нельзя.

```js
const clone = document.body.cloneNode(true);
const src = document.body.querySelectorAll('input,textarea,select,option');
const dst = clone.querySelectorAll('input,textarea,select,option');
for (let i = 0; i < src.length; i++) {
  const s = src[i], d = dst[i];
  if (s.type === 'checkbox' || s.type === 'radio') d.toggleAttribute('checked', s.checked);
  else if (s.tagName === 'OPTION') d.toggleAttribute('selected', s.selected);
  else if ('value' in s) d.setAttribute('value', s.value);
  if (s.tagName === 'TEXTAREA') d.textContent = s.value;
}
```

Снапшот снимается оболочкой после каждого успешного хода и держится в
памяти как последний известный. На диск пишется по правилам §8.

### Исполнение

```js
const fn = new Function('return (async () => {' + code + '})()');
const v = await fn();
```

Возвращённое значение сериализуется и усекается до 10000 символов; это канал
чтения состояния (§7), поэтому лимит не может быть маленьким. Ошибки уходят
как `ok:false`.

### Watchdog

Нет `result` за 5 секунд → ход помечается неуспешным, оболочка предлагает
пересоздать образ.

Снапшот у зависшего образа **не запрашивается**: бесконечный цикл блокирует
поток фрейма, и `{type:'snap'}` не будет обработан никогда. Восстановление
идёт из снапшота, снятого после предыдущего успешного хода.

## 7. Контракт с моделью

Системный промпт, статичный:

```
Ты управляешь HTML-страницей. Отвечай ТОЛЬКО кодом JavaScript.
Без markdown, без объяснений, без обратных кавычек.

Код исполняется в контексте страницы, тебе доступен document.
Отвечай пользователю не текстом, а изменением DOM: пиши в #out, меняй
элементы, создавай новые. Форму ответа выбираешь сама.

Страница создана из такой заготовки:
  <textarea id="q">   свободный ввод пользователя
  <ul id="items">     список
  <div id="out">      область вывода
  <div id="notes">    твои заметки, скрыт от пользователя
Ты и пользователь с тех пор могли изменить что угодно, включая эти узлы.

Снимка страницы тебе никто не присылает. Если нужно знать состояние —
верни нужное из кода, результат придёт следующим ходом:
  return [...document.querySelectorAll('[id]')].map(n => n.id).join()
  return document.querySelector('#items').innerHTML

Не трать ход на чтение, если можешь прочитать и изменить в одном коде:
  const box = document.querySelector('#items') ?? make('#items')
  if (box.children.length) { ... } else { ... }

Состояние храни в DOM — в узлах и data-* атрибутах. Заметки себе пиши
в #notes. Между ходами ничего кроме DOM не сохраняется.

Пользователь правит страницу руками — в полях ввода и через инструменты
разработчика браузера. Его правки приходят тебе дифом.

Ничего делать не обязательно: пустой ответ — законный ход.
```

### Разбор ответа

0. **Срезать рассуждения.** Обе локальные модели пользователя объявляют
   `capabilities: thinking`, в конфиге `thinkingFormat: "openai"`. Берём
   текстовый канал потока pi-ai, а не канал рассуждений; дополнительно
   защитно вырезаем блоки `<think>…</think>` для провайдеров, которые
   вкладывают их в текст.
1. снять обёртку из обратных кавычек
2. отрезать префиксы вида `Вот код:` / `Here is`
3. пустой ответ после очистки → ход успешен, ничего не исполняется
4. проверить парсинг через `new Function(code)`; синтаксическая ошибка →
   один автоповтор с текстом ошибки, затем показать ошибку

Результат исполнения уходит в историю сообщением
`user: результат: <значение>` — это и есть канал чтения состояния.

## 12. Приёмочные проверки

1. Нет `~/.pi/agent/models.json` → текст ошибки в UI, приложение живо
2. Два провайдера в конфиге → оба в селекторе
3. Провайдер без массива `models` → его модели всё равно в селекторе
4. `"apiKey": "$VAR"` разворачивается из окружения
5. Ключи и `baseUrl` отсутствуют в сетевом трафике браузера — проверяется и для
   `auth.json`, и для `models.json`, и **отдельно для канала заметок**.
   Заметки не проходят через allow-list `publicModels` и пишутся в пяти разных
   местах; дважды именно через них `baseUrl` и утекал. Проверка «в заметке нет
   подстроки `http`» недостаточна: при опечатке в схеме `baseUrl` попадает в
   текст исключения `fetch` без неё. Требование закрывается структурно — все
   `baseUrl` кладутся в множество для `scrub`, — а не дисциплиной авторов
   заметок.
6. Правка поля → диф содержит старое и новое значение
7. Удаление узла в DevTools → диф содержит строку удаления с HTML узла
8. Две подряд правки одного атрибута → в дифе одна строка, старое от первой
   правки, новое конечное
9. Код модели изменил элемент → в дифе этой правки нет
10. После отправки буферы очищены, повторная отправка даёт пустой диф
11. Ни один запрос к провайдеру не содержит снапшота образа
12. Незапрошенное сообщение `diff` от образа отбрасывается оболочкой
13. Правка во время хода → уезжает следующим ходом, не теряется
14. Пустой ответ модели → ход успешен, образ не тронут
15. Текст вместо кода → ошибка показана, образ не тронут
16. Ответ модели с рассуждениями → рассуждения срезаны, исполнен только код
17. `return document.body.innerHTML` на образе в 8000 символов → значение
    доходит до модели неусечённым сообщением `результат:`
18. Два хода подряд с исключением → история сброшена, следующий запрос
    содержит карту образа, и в карте нет пользовательского текста
19. `fetch('https://example.com')` из кода модели падает
20. `localStorage` из кода модели бросает `SecurityError`
21. Пауза во время хода → поток прерван, код не применён
22. Бесконечный цикл в коде модели → watchdog через 5 с, образ пересоздаётся
    из последнего снапшота, состояние предыдущего хода на месте

## 13. Известные слабости

- **Асинхронный хвост кода модели.** Мутации из `setTimeout` или из
  продолжения после `await`, пришедшие позже грейса в 250 мс, будут
  засчитаны человеку и уедут в диф. Модель увидит собственную работу как
  чужую правку.

- **Правка человека по узлу, который трогала модель, во время хода.** Пока
  код модели ждёт на `await`, поток свободен, и человек может править через
  DevTools. Атрибуция в грейс-окне идёт по множеству узлов, которых модель
  уже касалась: правка по другому узлу доедет, правка по тому же будет
  списана на модель и потеряется. Сузить дальше нечем — `MutationObserver`
  не сообщает авторства.

- **Холодный старт.** До первого сброса модель знает состояние только из
  истории собственного кода. На самом первом ходе она не знает ничего, кроме
  описания заготовки в системном промпте. Карта выдаётся только при сбросе.

- **Расхождение представления.** Картина образа у модели строится из истории
  её кода и через десятки ходов расходится с реальностью. Симптом:
  `querySelector` возвращает null. Лечится сбросом по двум ошибкам и
  запросом состояния (§7).

- **Крупная правка съедает контекст.** Диф без потолка: одна команда
  Edit as HTML над большим поддеревом уходит в контекст целиком и может
  сама тригернуть сброс. Решение принято осознанно.

- **Гонка человека и модели.** Ход, начатый до правки, вернётся с кодом по
  устаревшей картине и может затереть введённое. Цена — редкая потеря одной
  правки.

- **Локальные модели плохо держат «только код».** Разбор должен быть
  снисходительным; при неудаче — grammar провайдера, не удлинение промпта.

- **Человек в DevTools может сломать образ** так, что модель этого не поймёт:
  например переименовать `id`, на которые она опирается. Диф это покажет, но
  связать переименование с последующим null модель обязана сама.
