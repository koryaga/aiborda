# Ядро на pi SDK: спецификация редизайна

Дата: 2026-08-20. Заменяет `2026-08-19-dom-agent-design.md` в частях §3, §4,
§5, §7; §6 (протокол и сборка дифа) сохраняется целиком.

## Сдвиг

Было: собственный агент, который отвечает кодом, исполняемым в песочнице.
Модель всемогуща внутри образа и бессильна снаружи.

Стало: обычный агент с инструментами на ядре pi. Модель всемогуща снаружи —
`bash`, `curl`, файловая система, — а до страницы достаёт одним инструментом.
Страница остаётся единственным интерфейсом с человеком.

Причина: задача сформулирована как «универсальный агент, общающийся с
пользователем и миром через страницу». Путь через расширение возможностей
страницы упирается в CORS, который снятием песочницы не снимается. Путь через
инструменты агента даёт мир сразу и попутно убирает половину нашего кода.

## Проверенное перед проектированием

Факты из установленного `@earendil-works/pi-coding-agent@0.84.2` и со стендов.
Не перепроверять, альтернатив не изобретать.

**SDK.** `createAgentSession(options)` из `@earendil-works/pi-coding-agent`
возвращает `{session, extensionsResult, modelFallbackMessage}`. Опции включают
`cwd`, `agentDir`, `model`, `thinkingLevel`, `scopedModels`, `tools`,
`excludeTools`, `customTools`, `noTools`, `sessionManager`, `settingsManager`.

**AgentSession.** `prompt(text, options)` запускает ход; `subscribe(listener)`
отдаёт поток событий и возвращает функцию отписки. Типы событий, снятые на
живых ходах: `agent_start`, `turn_start`, `message_start`, `message_update`,
`message_end`, `tool_execution_start`, `tool_execution_end`, `turn_end`,
`agent_end`, `agent_settled`; есть `abort()`,
`waitForIdle()`, `steer()`, `followUp()`, `setModel()`, `cycleModel()`,
`setThinkingLevel()`, `getAllTools()`, `setActiveToolsByName()`.

**ToolDefinition.** Поля `name`, `label`, `description`, `parameters`
(схема TypeBox), `execute(toolCallId, params, signal, onUpdate, ctx)`,
необязательные `promptSnippet`, `promptGuidelines`, `executionMode`.
`typebox` — peer-зависимость pi.

**Разделение по origin даёт HTML5 и изоляцию одновременно.** Стенд: оболочка
на `127.0.0.1:8734`, образ на `127.0.0.1:8735`, никакого атрибута `sandbox`.

| проверка | результат |
|---|---|
| `localStorage`, `sessionStorage`, `indexedDB`, `cookie` | работают |
| `isSecureContext` | `true` |
| `parent.document` | `SecurityError` |
| запись в DOM оболочки | `SecurityError` |
| `fetch` к origin оболочки | `TypeError` |
| `event.origin` в оболочке | `http://127.0.0.1:8735` |

Это строго лучше `allow-same-origin`: тот даёт хранилища ценой полного доступа
к оболочке, включая возможность снять собственный `sandbox` (тоже проверено).

**WebSocket из образа работает** и не подчиняется CORS — соединение с внешним
сервером открылось и вернуло эхо. Существующая дыра в прежней модели угроз;
при новой архитектуре она перестаёт быть дырой, потому что выход наружу и так
разрешён.

## Архитектура

```
dom-agent (один процесс Node)
  ├ ядро    createAgentSession        модель, контекст, bash, curl, ФС
  ├ :8730   оболочка                  index.html, shell.js
  └ :8731   образ                     image.html, image-boot.js, seed
```

Два порта — весь механизм изоляции. Атрибут `sandbox` не используется.

Оболочка и образ общаются через `postMessage`, как и прежде, но теперь
`event.origin` — настоящее значение и проверяется наравне с `event.source`
и совпадением `id`.

## Инструмент страницы

Один: `page_exec`.

```
name:        page_exec
label:       Страница
description: Исполнить JavaScript в странице пользователя и вернуть результат.
             Это единственный способ читать и менять то, что видит человек.
parameters:  { code: string }
executionMode: sequential
```

Возвращает сериализованное значение выражения, усечённое до 10000 символов,
либо текст ошибки. Покрывает и чтение, и запись: модель может прочитать
состояние и изменить его в одном вызове.

Второй инструмент (снимок, карта) не заводится заранее. Появится, если
замеры покажут, что модель спотыкается.

**Чтение состояния перестаёт стоить ход.** В прежней схеме модель возвращала
значение и получала его следующим ходом; теперь читает и действует внутри
одного хода. Это закрывает слабость «холодный старт» из §13 прежней спеки.

## Цикл хода

1. Человек правит страницу: поля, DevTools, `contenteditable`
2. Наблюдатель мутаций копит правки (§6 прежней спеки, без изменений)
3. Человек жмёт «отправить»
4. Оболочка запрашивает у образа диф
5. Оболочка отправляет диф в dom-agent
6. dom-agent зовёт `session.prompt(diff)`
7. Модель внутри одного хода вызывает что угодно: `page_exec`, `bash`, `read`,
   `write` — сколько угодно раз
8. События сессии транслируются в оболочку для показа

## Канал сервер → образ

Новое требование: сервер должен инициировать `page_exec` посреди хода, а не
только отвечать на запросы оболочки.

Оболочка держит открытый **SSE** (`GET /api/events`): по нему сервер шлёт вниз
запросы `page_exec` и события сессии. Обратный ход — обычный
`POST /api/page-result`. Оболочка остаётся посредником: сервер до образа
напрямую не достаёт, образ до сервера тоже.

WebSocket рассматривался и отклонён при реализации: в Node есть
WebSocket-клиент, но нет сервера, а пакет `ws` стал бы первой зависимостью
помимо pi. SSE-код уже был написан и покрыт тестами.

Тонкость, стоившая отладки: `res.writeHead()` сам по себе заголовки в сокет
не отправляет. Без явного `res.flushHeaders()` подписка на `/api/events`
висит до первого события, которого может не быть долго, — и весь канал
«сервер сам инициирует ход» оказывается мёртвым, чего юнит-тесты не
показывают.

## Разрешения

Гейтов нет: инструменты доступны модели сразу, включая `bash` и `write`.
Решение принято сознательно для первой версии. Практическое следствие: агент
имеет полномочия пользователя на машине, как `pi` без подтверждений.

Из этого прямо следует, что prompt injection становится значимым риском, как
только модель начнёт читать содержимое чужих сайтов. Смягчений в этой версии
нет; это записано как известная слабость, а не как недосмотр.

## Что удаляется

- `server/pi-config.js` — провайдеров и ключи ведёт pi
- `server/pi-settings.js` — `scopedModels` и `SettingsManager` штатные
- `server/context.js` — историю, сжатие и сброс ведёт pi
- `server/parse.js` — **задача исчезает**: модель не отвечает кодом в свободной
  форме, она вызывает инструмент. Срезание рассуждений, снятие обёрток,
  вводные фразы и автоповтор при неразбираемом коде перестают существовать
- большая часть `server/index.js`
- их тесты — около 130 из 173

## Что сохраняется без изменений

Весь `web/image-boot.js`: наблюдатель мутаций, атрибуция по окну исполнения,
коалесцирование, сборка дифа, снапшот. Вместе с 34 тестами. Это самая ценная
часть проекта, и редизайн её не касается.

Меняется только загрузка: образ становится настоящей страницей на своём порту,
`image-boot.js` подключается обычным `<script src>` вместо инлайна в `srcdoc`.

## Инварианты

1. **Модель всемогуща снаружи через инструменты pi, а до страницы достаёт
   только через `page_exec`. Страница до оболочки не достаёт — разные origin.**
   Прежняя формулировка переворачивается: ограничивается не модель, а страница.

2. **Диф остаётся единственным автоматическим каналом восприятия.** Состояние
   страницы не попадает в контекст само; модель читает его явным вызовом
   `page_exec`, когда сочтёт нужным. Снимок страницы не отправляется никогда.

Второй инвариант — тот же, что и прежде, и он единственная причина, по которой
сборка дифа сохраняется в полном объёме.

## Контракт с моделью

Системный промпт переписывается. Существенные отличия от прежнего:

- модель отвечает не кодом, а вызовами инструментов
- у неё есть `bash`, файлы и сеть — страница не единственная её возможность
- **`localStorage` работает и переживает пересоздание страницы**, в отличие от
  DOM. Прежняя фраза «между ходами ничего кроме DOM не сохраняется» неверна и
  удаляется. Это закрывает первый пункт `TODO.md`.
- заметки себе по-прежнему в `#notes`, состояние интерфейса — в DOM,
  долговременное состояние — в `localStorage`

## Что не входит

Подтверждения опасных действий. Расширение как второй режим запуска — описано
в `docs/alternative-pi-plugin.md`. Очередь ходов, пауза, watchdog, журнал —
переносятся из прежней вехи 2 и пересматриваются после редизайна. Брокер
сетевых вызовов из страницы: не нужен, сеть даёт pi.

## Приёмочные проверки

1. Образ отдаётся с отдельного порта и не имеет атрибута `sandbox`
2. `localStorage.setItem` в коде модели работает и переживает перезагрузку
   страницы
3. Код в образе не может прочитать `parent.document` — `SecurityError`
4. Код в образе не может обратиться к origin оболочки — `TypeError`
5. Оболочка проверяет `event.origin`, `event.source` и `id`; сообщение с чужим
   origin отбрасывается
6. Правка поля даёт диф, правка через DevTools даёт диф, правка кодом модели
   диф не даёт — как прежде
7. Модель читает состояние и меняет его в одном ходу
8. `bash` из модели выполняется и возвращает вывод
9. Снимок страницы не уходит в провайдера ни при каких условиях
10. Модель выбирается из `scopedModels`/настроек pi без нашего кода
11. Ход прерывается через `session.abort()`
