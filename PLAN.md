# DOM-агент: спецификация

Веб-приложение, в котором LLM живёт внутри страницы. Пользователь правит DOM
руками и нажимает «отправить». Модель получает диф правок, отвечает
JavaScript-кодом, код исполняется и меняет тот же DOM. Образ одновременно
интерфейс, состояние и память агента.

Инварианты:

1. Код модели всемогущ внутри образа и бессилен снаружи.
2. Состояние страницы не попадает в контекст извне. От пользователя приходит
   только диф; состояние модель читает сама, когда сочтёт нужным.

---

## 1. Топология

| Контекст | Что это | Полномочия |
|---|---|---|
| Сайдкар | Node-процесс | ФС, сеть, ключи, конфиг pi, история контекста |
| Оболочка | страница в браузере | кнопки «отправить», «пауза», «сброс»; индикатор |
| Образ | `<iframe sandbox="allow-scripts">` | только свой DOM |

Образ имеет opaque origin: нет `localStorage`, нет доступа к `parent`,
`fetch` уходит с `Origin: null` и умирает на CORS, навигация запрещена.

Кнопки находятся в оболочке, вне iframe: код модели не должен мочь их убрать
или нажать.

### Seed образа (`web/seed.html`)

```html
<textarea id="q" rows="3"></textarea>
<ul id="items"></ul>
<div id="out"></div>
<div id="notes" hidden></div>
```

Модель вправе менять что угодно, включая seed.

### Вне объёма v1

Поля промпта и чата нет. Approval-гейта нет. Доступа модели к ФС и сети нет.
Бандлера и React нет: один HTML и ES-модули.

## 2. Цикл хода

1. Человек правит образ
2. Доверенные события помечают изменённые элементы (§5)
3. Человек жмёт «отправить»
4. Оболочка запрашивает у образа диф; при `needAnchor` — ещё и снапшот
5. Сайдкар собирает контекст, зовёт модель, стримит ответ
6. Код применяется в образе, пометки снимаются

Один ход за раз. Правки во время хода копятся пометками и уезжают следующим
ходом. Повторное «отправить» ставит в очередь ровно один отложенный ход.

«Пауза» прерывает текущий ход и блокирует отправку.

## 3. Сборка контекста

История хранится в сайдкаре, per-session. Снапшота в контексте нет никогда.

```
system:     контракт (§7), статичный, включая описание окружения
user:       диф правок человека
assistant:  <код>
user:       результат: <возвращённое значение>     ← если код что-то вернул
assistant:  <код>
user:       диф правок человека
```

Правила:

- снапшот образа в запрос к провайдеру не кладётся ни при каких условиях
- снапшот не кладётся в системный промпт
- отправленные сообщения не редактируются и не удаляются по одному
- `system` не меняется между ходами
- если код вернул значение — оно уходит следующим сообщением `результат: ...`;
  если вернул `undefined` — сообщение не добавляется

Префикс не переписывается, KV-кэш переиспользуется: префилл платится только
за новый диф.

### Сброс истории

`history = []`. Без суммаризации и без якоря.

Триггеры:

- оценка контекста превысила 60% от `contextWindow` модели; если поле
  отсутствует — 24k токенов по оценке 4 символа на токен
- два хода подряд завершились ошибкой исполнения
- кнопка «сброс → история» в оболочке

После сброса модель не знает состояния страницы, поэтому сайдкар один раз
добавляет к следующему дифу строку:

```
[история сброшена, состояние страницы тебе неизвестно]
```

Это подсказка на десяток токенов, а не якорь. Дальше модель сама решает,
читать состояние или обойтись.

## 4. Конфигурация моделей из pi

Читаем `~/.pi/agent/models.json`:

```json
{
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "ollama",
      "models": [{ "id": "qwen3.5:9b" }, { "id": "lfm2.5:8b-a1b" }]
    }
  }
}
```

- путь по умолчанию `~/.pi/agent/models.json`; переопределяется
  `PI_MODELS_PATH` и флагом `--pi-config`
- `api`: поддержать `openai-completions` и `anthropic-messages`; прочие
  распознать, пометить unsupported, не падать
- у модели обязателен только `id`; `contextWindow`, `cost`, `input` опциональны
- `compat.supportsDeveloperRole: false` → системный промпт ролью `system`
- ключ: `apiKey` из models.json, иначе `~/.pi/agent/auth.json`, иначе окружение
- auth.json имеет права 0600: не логировать, не отдавать в браузер
- конфиг отсутствует или битый → пустой список моделей и текст ошибки
  «не найден ~/.pi/agent/models.json — создайте его или укажите --pi-config»
- перечитывать по SIGHUP и `POST /api/reload`

Браузеру уходит только `{provider, id, contextWindow}`.

**Шаг 0:** проверить, читает ли `@earendil-works/pi-ai` файл models.json сам.
Если да — использовать его вместо собственного загрузчика. Решение записать
в README.

## 5. Сайдкар: HTTP API

```
GET  /api/models          -> { models: [{provider, id, contextWindow}], error? }
POST /api/reload          -> перечитать конфиг
GET  /api/session         -> { tokens: int, limit: int }
POST /api/session/reset   -> сбросить историю
POST /api/commit          -> SSE-поток хода
POST /api/abort           -> прервать текущий ход
```

`POST /api/commit`:

```json
{
  "model": { "provider": "ollama", "id": "qwen3.5:9b" },
  "diff": "#q  \"\" -> \"посчитай маржу\"\n#mode  fast -> exact"
}
```

Снапшот в теле запроса отсутствует. Оболочка снимает снапшот только для
журнала (§8), не для контекста.

SSE-события: `delta`, `done` (итоговый код), `error`.

Сайдкар слушает `127.0.0.1`. Оболочка отдаётся тем же процессом.

## 6. Протокол оболочка ↔ образ

`postMessage`.

Оболочка → образ: `{type:'exec', id, code}`, `{type:'diff', id}`,
`{type:'snap', id}`, `{type:'reset'}`

Образ → оболочка: `{type:'ready'}`, `{type:'result', id, ok, value?, error?}`,
`{type:'diff', id, text}`, `{type:'snap', id, html}`

### Пометка правок человека

`isTrusted` выставляется браузером и не подделывается из скрипта, поэтому код
модели пометок не оставляет.

```js
for (const t of ['input', 'change', 'click']) {
  document.addEventListener(t, e => {
    if (!e.isTrusted) return;
    const el = e.target;
    if (!el.hasAttribute('data-was')) {
      el.setAttribute('data-was', el.value ?? el.textContent ?? '');
    }
    el.setAttribute('data-edited', '1');
  }, true);
}
```

Удаления: при `keydown` Delete/Backspace на выделенном узле записать факт
удаления в буфер образа.

Диф строится обходом `[data-edited]` плюс буфер удалений:

```
#q       "" -> "посчитай маржу по регионам"
#mode    fast -> exact
#row-3   удалён
```

После сборки дифа `data-edited` и `data-was` снимаются, буфер очищается.

### Сериализация снапшота

`innerHTML` не содержит `input.value`, `checked`, `selected` и содержимое
`textarea`. Перед снапшотом:

```js
for (const el of document.querySelectorAll('input,textarea,select,option')) {
  if (el.type === 'checkbox' || el.type === 'radio') el.toggleAttribute('checked', el.checked);
  else if (el.tagName === 'OPTION') el.toggleAttribute('selected', el.selected);
  else if ('value' in el) el.setAttribute('value', el.value);
  if (el.tagName === 'TEXTAREA') el.textContent = el.value;
}
```

### Исполнение

```js
const fn = new Function('return (async () => {' + code + '})()');
const v = await fn();
```

Возвращённое значение сериализуется и усекается до 10000 символов; это канал
чтения состояния (§7), поэтому лимит не может быть маленьким. Ошибки уходят
как `ok:false`.

Watchdog: нет `result` за 5 секунд → предложить пересоздать iframe,
предварительно предложив сохранить снапшот.

## 7. Контракт с моделью

Системный промпт, статичный:

```
Ты управляешь HTML-страницей. Отвечай ТОЛЬКО кодом JavaScript.
Без markdown, без объяснений, без обратных кавычек.

Код исполняется в контексте страницы, тебе доступен document.
Отвечай пользователю не текстом, а изменением DOM: пиши в #out, меняй
элементы, создавай новые. Форму ответа выбираешь сама.

Страница создана из такой заготовки:
  <textarea id="q">   свободный ввод пользователя
  <ul id="items">     список
  <div id="out">      область вывода
  <div id="notes">    твои заметки, скрыт от пользователя
Ты и пользователь с тех пор могли изменить что угодно, включая эти узлы.

Снимка страницы тебе никто не присылает. Если нужно знать состояние —
верни нужное из кода, результат придёт следующим ходом:
  return [...document.querySelectorAll('[id]')].map(n => n.id).join()
  return document.querySelector('#items').innerHTML

Не трать ход на чтение, если можешь прочитать и изменить в одном коде:
  const box = document.querySelector('#items') ?? make('#items')
  if (box.children.length) { ... } else { ... }

Состояние храни в DOM — в узлах и data-* атрибутах. Заметки себе пиши
в #notes. Между ходами ничего кроме DOM не сохраняется.

Пользователь правит страницу руками. Его правки приходят тебе дифом.

Ничего делать не обязательно: пустой ответ — законный ход.
```

Результат исполнения уходит в историю сообщением
`user: результат: <значение>` — это и есть канал чтения состояния.

### Разбор ответа

1. снять обёртку из обратных кавычек
2. отрезать префиксы вида `Вот код:` / `Here is`
3. пустой ответ после очистки → ход успешен, ничего не исполняется
4. проверить парсинг через `new Function(code)`; синтаксическая ошибка →
   один автоповтор с текстом ошибки, затем показать ошибку

## 8. Персистентность

`.dom-agent/log.jsonl`, append-only:

```json
{"seq":41,"ts":"...","model":"ollama/qwen3.5:9b","diff":"...","code":"...","ok":true,"ms":2310}
```

Снапшот образа в `.dom-agent/snapshots/NNN.html` каждые 10 ходов, при сбросе
истории и при выходе.

Восстановление: последний снапшот плюс доигрывание кода последующих ходов.
Отдельной модели данных нет: журнал `exec` и есть журнал мутаций.

## 9. UI оболочки

```
┌──────────────────────────────────────────────┐
│                                              │
│                  ОБРАЗ                       │
│                 (iframe)                     │
│                                              │
├──────────────────────────────────────────────┤
│ [модель ▾]  ● 12k/32k    [пауза] [сброс] [→] │
└──────────────────────────────────────────────┘
```

- `→` собирает диф и отправляет ход; Ctrl/Cmd+Enter дублирует
- точка: свободна / думает / ошибка
- счётчик: оценка токенов и порог сброса
- «сброс» — меню: история / образ к seed

Клавиатурная доступность, видимый фокус, `prefers-reduced-motion`,
вменяемо до 900px.

## 11. Порядок реализации

**0.** Проверить `@earendil-works/pi-ai`, решение в README.

**1.** Сайдкар, `/api/models`, селектор моделей в оболочке.
Готово: селектор показывает модели из реального models.json.

**2.** Образ, seed, `exec`/`snap`, ручной ввод кода в оболочке, без LLM.
Готово: ручной JS меняет образ, ошибка возвращается корректно.

**3.** Пометки по `isTrusted`, сборка дифа, кнопка «отправить», синхронизация
живых значений формы. Диф печатается в консоль, модель не подключена.
Готово: правка трёх элементов даёт корректный трёхстрочный диф; код,
исполненный в образе, пометок не оставляет.

**4.** `/api/commit`, `openai-completions`, только дифы, применение кода,
возврат значения в историю сообщением `результат:`.
Готово: правка `#q` на «сделай список из трёх пунктов» даёт список в образе.

**5.** Контекст: счётчик, порог, сброс по размеру и по двум ошибкам подряд,
подсказка о сбросе в следующем дифе.
Готово: после сброса ход отрабатывает не хуже, чем до.

**6.** Очередь, пауза, прерывание, индикатор.

**7.** Замерить долю ходов, где код исполнился с первой попытки, на
qwen3.5:9b. Цифра идёт в README; от неё решается вопрос о grammar-режиме.

**8.** Журнал, снапшоты, восстановление.

## 12. Приёмочные проверки

1. Нет `~/.pi/agent/models.json` → текст ошибки в UI, приложение живо
2. Два провайдера в конфиге → оба в селекторе
3. Ключи и baseUrl отсутствуют в сетевом трафике браузера
4. Правка `#q` → диф содержит старое и новое значение
5. Код модели изменил элемент → `data-edited` не появился
6. После отправки пометки сняты, повторная отправка даёт пустой диф
7. Ни один запрос к провайдеру не содержит снапшота образа
8. Правка во время хода → уезжает следующим ходом, не теряется
9. Пустой ответ модели → ход успешен, образ не тронут
10. Текст вместо кода → ошибка показана, образ не тронут
11. `return document.body.innerHTML` на образе в 8000 символов → значение
    доходит до модели неусечённым сообщением `результат:`
12. Два хода подряд с исключением → история сброшена, следующий диф содержит
    пометку о сбросе
13. `fetch('https://example.com')` из кода модели падает
14. `localStorage` из кода модели бросает `SecurityError`
15. Пауза во время хода → стрим прерван, код не применён

## 13. Известные слабости

- **Холодный старт и старт после сброса.** Модель не знает состояния и может
  потратить ход на чтение вместо действия. Смягчается описанием заготовки
  в системном промпте и указанием читать и действовать в одном коде.
  Замерить на шаге 7 долю ходов, потраченных только на чтение.

- **Расхождение представления.** Картина образа у модели строится из истории
  её кода и через десятки ходов расходится с реальностью. Симптом:
  `querySelector` возвращает null. Лечится сбросом по двум ошибкам и
  запросом состояния (§7).

- **Бесконечный цикл** в коде модели вешает iframe; лечится пересозданием.

- **Мусор от contentEditable:** `<br>`, обёрточные `<div>`, инлайновые `style`.

- **Гонка человека и модели.** Ход, начатый до правки, вернётся с кодом по
  устаревшей картине и может затереть введённое. Цена — редкая потеря одной
  правки.

- **Локальные модели плохо держат «только код».** Разбор должен быть
  снисходительным; при неудаче — grammar провайдера, не удлинение промпта.

- **Удаления в дифе** ловятся хуже правок: покрыто только явное удаление
  выделенного узла.
